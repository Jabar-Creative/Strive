C-03 — UI Dompet

Design brief · Senin 28 Sep 2026 · Dev B (Kemal) · dokumen sesi auto mode, ikut ter-commit sebagai bahan review

1 · Ringkasan fitur

Masalah. Saldo Strive Coins pengguna berubah oleh banyak hal (lesson, streak, scan, store, penahanan saat pekerjaan berjalan) dan sampai hari ini tidak ada layar yang menunjukkan kenapa. Satu-satunya jawaban tersedia adalah bertanya ke support.

Sebelum. /wallet hanya stub PageStub bertuliskan "C-03".

Sesudah. Satu layar menampilkan saldo terkini, 20 entri terakhir, penelusuran riwayat lengkap sampai entri pertama (cursor pagination, tombol muat lagi), dan penjelasan bahasa manusia untuk setiap jenis entri. Target AC: pengguna bisa menjawab sendiri "kenapa saldo saya berubah" tanpa menghubungi support.

Setiap baris bisa diketuk untuk penjelasan jenis entri. Tahan lalu kembali = pekerjaan gagal dan koin dikembalikan penuh.

Aturan tampilan baris:

  • Delta memakai CoinPill variant="delta" (warna mengikuti tanda).
  • Baris hold tampil sebagai penahanan (bukan pengeluaran final), release sebagai pengembalian, adjust berkomentar "koreksi sistem" tanpa menyalahkan pengguna.
  • note dari server (bila ada) ditampilkan menggantikan teks bawaan.
  • Saldo-setelah memakai balance_after server, tidak dihitung client.

6 · Skenario negatif

Sesi habis (401)Pesan sesi berakhir + tautan ke /login (bukan redirect paksa; konsisten pola L-04)
Cursor basi/dikorupsi (400 INVALID_CURSOR)Daftar yang sudah tampil tetap; tombol muat menampilkan galat dan bisa dicoba ulang dari awal
Riwayat kosongEmpty state menjelaskan cara mendapat koin (belajar, streak), bukan layar kosong polos

prefers-reduced-motionSemua animasi durasi 0
Viewport 360pxTanpa scroll horizontal; angka dan label tidak terpotong

7 · Titik verifikasi terbuka

  • Verifikasi visual di browser 360px dan staging — sesi auto mode ini tidak punya alat browser (MCP chrome-devtools tidak terpasang), jadi bukti visual menyusul dari pemeriksaan manual / staging seperti alur L-04.
  • Data nyata berisi transaksi campuran (hold, release, adjust) baru lengkap di staging setelah alur scan dan store hidup (kredensial vendor).
  • Empty state dan copy penjelasan jenis entri idealnya dibaca ulang oleh non-engineer sebelum dianggap final.
