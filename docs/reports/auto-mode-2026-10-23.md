# Laporan Auto Mode — 23 Okt 2026 (setup lingkungan, bukan kode repo)

Permintaan: cek apakah rtk terpasang (kalau tidak, pasang), audit "Claude setups", dan cari kenapa token usage bar tidak muncul. Semua perubahan ada di luar repo ini; laporan ini satu-satunya file repo.

## Apa yang dikerjakan

1. **rtk belum terpasang, sekarang terpasang.** rtk = `rtk-ai/rtk`, binary Rust tunggal yang memadatkan output perintah shell sebelum masuk konteks model. Dipasang lewat installer resmi (`install.sh` dari repo mereka) ke `~/.local/bin/rtk`, versi 1.0.1, checksum SHA-256 diverifikasi installer. Aktivasi: hook `PreToolUse` (matcher `Bash`, command `/home/kali/.local/bin/rtk hook claude`) ditambahkan ke `~/.claude/settings.json`, plus `RTK.md` dan referensi `@RTK.md` di `~/.claude/CLAUDE.md` (keduanya ditulis `rtk init -g` sendiri).
2. **Token usage bar hilang karena tiga bug di `~/.claude/statusline-command.sh`**, semuanya khas skrip port-an dari macOS (handoff laptop). Sudah diperbaiki:
   - `stat -f %m` (sintaks BSD) di Linux "sukses" dengan dump filesystem, bukan mtime, lalu aritmetika umur cache meledak (exit 1). Dibalik: GNU `stat -c %Y` dulu, BSD fallback.
   - Respons kuota GLM berbentuk `{"code":200,...}` tapi skrip mengecek `.success == true`, jadi setiap fetch sukses dibuang dan cache kuota stagnant sejak 24 Agu (60 hari). Sekarang menerima `.code == 200` ATAU `.success == true`.
   - Baris terakhir `[ ... ] && echo` mengembalikan exit 1 setiap kali baris kedua kosong, dan Claude Code membuang seluruh statusline. Ditutup dengan `exit 0`.
3. **Audit setup Claude**: settings.json valid, 4 plugin aktif (superpowers, frontend-design, code-simplifier, diagram-design), 8 agent lengkap di `~/.claude/agents/`, 31 skill di `~/.claude/skills/`. Satu komponen MATI: MCP `hexstrike-ai` menunjuk `/home/kali/hexstrike-ai/hexstrike_mcp.py` yang tidak ada (foldernya tidak ada di mesin ini). Tidak diutak-atik; butuh keputusan: pasang ulang hexstrike, atau buang entrinya dari settings.

## Verifikasi yang dijalankan beserta hasilnya

- `echo <payload> | bash statusline-command.sh` SEBELUM perbaikan: error aritmetika, exit 1, bar tidak pernah dirender. SESUDAH: dua baris penuh, `⏱️ 5h ... 1% (4h 53m)` dan `📅 7d ██░░░░░░ 20% (6d 15h)`, exit 0.
- Endpoint kuota GLM dites langsung dengan token sesi ini: `{"code":200}`, limit 5 jam 1%, 7 hari 20%. Cache `~/.claude/.cache/glm-quota.json` ter-refresh live (umur 44 detik saat dicek).
- Hook rtk dibuktikan MENYALA dengan sentinel sementara: dua panggilan Bash menghasilkan dua entri log, lalu sentinel dibongkar dan settings dikembalikan bersih. `jq` valid di akhir; `statusLine` dan 4 plugin tidak tersentuh.
- `rtk --version` = 1.0.1; `rtk gain` sudah menghitung (6 perintah, 154 token input), artinya hook sudah aktif menulis ulang perintah sejak sesi ini.

## Yang dilewati beserta alasannya

- Tidak menjalankan `agent-security` penuh: tidak ada kode aplikasi yang berubah. Pemeriksaan yang tetap dilakukan: installer resmi dengan checksum wajib dan penolakan path-traversal; binary di PATH user biasa (bukan root); tidak ada secret baru ditulis (kunci provider sudah ada di settings sebelumnya dan tidak digandakan ke laporan ini); perubahan skrip statusline hanya penukaran urutan stat, pelebaran cek jq, dan `exit 0`.

## Kelemahan fondasi yang ditemukan

- Skrip statusline hasil handoff macOS tidak pernah diuji di Linux: dua dari tiga bug membuatnya gagal diam-diam. Pola yang sama dengan jebakan "build hijau tapi rusak saat dijalankan" di CLAUDE.md repo: verifikasi artinya menjalankannya, bukan membacanya.
- `rtk init -g` dalam mode non-interaktif MENOLAK menambal settings.json (default N pada prompt y/N), jadi patch hook dilakukan manual sesuai snippet resminya. Kalau kelak `rtk init -g` dijalankan lagi dan promptnya dijawab y, hasilnya idempoten.
