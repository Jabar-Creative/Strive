Lingkungan: lokal (web :3000 · API :3001 · PostgreSQL/Redis/MinIO Docker) Status: seluruh skenario lulus Tanggal: 2026-10-18 Bukti user: strive-n02-p*&commat;yopmail.com (dibuat per run)

1 · Ringkasan fitur

Mahasiswa kini melihat lonceng notifikasi di navigasi setiap layar student: lencana jumlah belum dibaca (dihitung server, bukan klien), panel daftar notifikasi terbaru-dulu, dan menandai dibaca bersifat optimistik yang pulih otomatis kalau permintaan gagal (PRD §7 E16 NO-7). Di Hub, banner menampilkan peringatan streak (streak_warning) belum dibaca yang terbaru; menutupnya menandai notifikasi itu dibaca. Lonceng dan banner berbagi SATU state lewat NotificationProvider supaya lencana dan banner tidak pernah saling melenceng.

5 · Keputusan teknis yang diambil

  • unread_count dihitung SERVER (query COUNT terpisah, bukan dari isi halaman): pengguna yang lama tidak membuka aplikasi punya belum-dibaca lebih banyak dari halaman pertama; menghitung di klien salah secara konstruksi. Perubahan kontrak bersifat aditif (Dev B pemilik packages/contracts).
  • Stempel waktu masuk sebagai parameter eksplisit ke mesin (bukan new Date() di dalamnya) supaya unit test deterministik — pola C-03.
  • Guard klik ganda di mesin (sedangDitandai), bukan cuma tombol disabled — pola L-04.
  • Tamu melihat kosong, bukan error: 401 → fase tanpaSesi → komponen null.
